# Usage-informed design

For substantive app work, consult `docs/usage-metrics.md` and, when present, the
local `.data/usage.sqlite` database read-only. Use accumulated evidence to volunteer
worthwhile design suggestions without waiting for the user to specify a feature
or problem. Keep this lightweight and relevant to the current task; do not repeat
suggestions or draw conclusions from sparse counts.

Suggestions are proactive; design changes still require a user request. Do not
redesign features, run experiments, or start scheduled evolution autonomously.
Preserve historical usage counts, label meaningful UI revisions, and distinguish
visibility from use. Never treat click maximization as the product goal.
